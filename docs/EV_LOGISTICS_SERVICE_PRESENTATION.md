# 일일 물류 배송 조회 서비스

## 서비스 개요

사원번호와 배차일을 기준으로 차량 배정부터 배송 도착 예상까지 확인하는 일일 물류 운영 서비스다. 부산항 신선대 컨테이너터미널에서 한진인천컨테이너터미널(HJIT)까지의 고정 노선을 기준으로 차량·화물·운행환경·배터리 상태를 반영한다.

## 서비스 정의

### 입력 및 자동 생성 항목

- 사원번호: 숫자 8자리
- 배차일
- 차량: `1호차 (Volvo FH)` 형식
- 화물 박스 수: 1박스 10kg, 최초 조회 시 3~10박스 자동 배정
- 평균속도: 기본 100km/h, 5km/h 단위 변경
- HVAC: 자동, 강제 ON, 강제 OFF
- 운전성향: 사원번호와 배차일을 기준으로 자동 생성
- 출발 배터리 SOC: 50~90% 중 5% 단위 자동 생성

운전성향 기준: `0.00~0.33` Eco / Smooth Driving, `0.34~0.66` Normal Driving, `0.67~1.00` Aggressive Driving

### 핵심 결과

결과 화면 상단에 사원번호, 차량번호, 출발 배터리 SOC, 화물 박스 수와 총 화물량, 충전 휴게소, 출발·예상 도착시간, 예상 에너지 소비량, 모델 설명력과 예상 오차를 표시한다.

### 운영 기준

- 배송 출발시간: 배차일 오전 10:00
- 노선 총거리: 465.6km
- 최소 안전 SOC: 10%
- 충전 목표 SOC: 충전이 필요한 경우 100%
- 충전 효율: 92%
- 충전 1회 추가 정차시간: 7분
- 충전 출력 미확인·운영 불가 휴게소는 추천 대상에서 제외
- 필요한 경우에만 충전해 충전 정차 횟수를 줄임

## 서비스 구현방법(간략)

1. 사원번호와 배차일을 SHA-256 기반 seed로 변환해 동일 입력에 동일한 배차·SOC·운전성향을 생성한다.
2. 차량 CSV에서 차량 사양과 적재 한도를 읽고 화물 박스 수를 검증한다.
3. 노선 설정 JSON과 휴게소 CSV를 순서·누적거리 기준으로 정렬하고, Copernicus DEM 기반 휴게소별 고도로 구간 평균경사를 적용한다.
4. 속도 제곱, 온도 편차, 적재량·경사도 결합 등 파생변수를 생성한다.
5. StandardScaler와 Linear Regression 모델을 사용하며 저장된 `models/energy_model.joblib`를 우선 재사용한다.
6. 실제 화물량과 타이어 공기압을 학습 데이터 범위로 변환하고 서비스 보정계수를 적용한다.
7. 휴게소 사이 각 구간의 거리와 평균경사를 모델에 개별 입력해 소비율과 소비에너지를 예측하고, 이를 누적해 SOC와 안전 여부를 판단한다.
8. 충전이 필요한 경우 이용 가능한 휴게소에서 100%까지 충전하고 충전시간·정차시간을 반영한다.
9. 배차일 10:00부터 주행·충전시간을 합산해 예상 도착시간을 계산한다.
10. 상세정보는 그룹화해 제공하고, 일일 배차기록을 CSV 또는 Excel로 저장한다.

## 저장 및 화면 동작

- 화면 하단에 `YY.MM.DD / 일일 배차기록`을 표시한다.
- 다운로드 파일에는 `사원번호`, `차량번호`, `배차 허가 여부`만 저장한다.
- 날짜는 파일명에만 포함한다.
- `메인화면으로 돌아가기`를 누르면 조회 결과와 사원번호 입력값을 초기화한다.
- 조회 결과를 보는 동안 사원번호와 배차일은 읽기 전용으로 잠긴다.
- `배차 상세정보`, `에너지·충전 정보`, `노선 정보`, `충전소 정보`는 접기/펼치기 영역에서 확인한다.
- `노선 정보`에는 17개 구간의 거리, 고도차, 평균경사, 경사각도, 예상 소비율, 구간 소비에너지를 순서대로 표시한다.

## 모델 성능

- 모델: Feature Engineering + StandardScaler + Linear Regression
- R²: 0.9417, 화면에서는 모델 설명력 94.2%로 표시
- MAE: 0.705kWh/100km
- RMSE: 0.887kWh/100km, 화면에서는 예상 오차 ±0.89kWh/100km로 표시
- 모델 파일을 저장해 서비스 실행 시 반복 학습하지 않고 재사용한다.

## 노선 경사도 데이터 조사 및 적용 이력

### 기존 데이터 확인

다음 프로젝트 파일에서 노선 경사도 또는 고도 컬럼이 있는지 확인했다.

- `datas/busan_port_hjit_service_route.csv`
- `docs/route_config_busan_port_hjit.json`
- `docs/PROJECT_DATA_GUIDE.md`
- `app/app.py`

기존 휴게소 노선 CSV에는 거리·충전기·운영 상태 정보만 있었고 경사도와 고도 정보는 없었다. 에너지 모델의 학습 데이터에는 `road_grade_pct`가 존재하지만, 서비스 앱에서는 실제 노선 경사 데이터를 찾지 못해 `0.0`을 고정 입력하고 있었다.

### 웹에서 확인한 데이터

- 위치 검색: [OpenStreetMap Nominatim Search API](https://nominatim.org/release-docs/latest/api/Search/)
- 고도 조회: [Open-Meteo Elevation API](https://open-meteo.com/en/docs/elevation-api)
- 고도 원천: Copernicus DEM, 약 90m 공간 해상도

Nominatim에서 출발지, 도착지, 휴게소 16곳의 좌표를 조회했다. 일부 휴게소는 최초 검색에서 부산방향 시설로 연결되어 `서울방향`을 포함한 명칭으로 다시 조회해 좌표를 보정했다. 출발지와 도착지는 프로젝트 설정에 저장된 주소를 기준으로 검색했다.

### 직접적인 도로 경사 데이터를 사용하지 못한 이유

검색 과정에서 현재 고정 노선 전체에 대해 사용할 수 있는 공개 도로 종단선형, 차로 중심선별 고도 프로파일 또는 휴게소 구간별 공식 평균경사 자료를 확인하지 못했다. 일반 지도 검색으로 확인되는 지점 고도만으로는 터널·교량·절토·성토 구간과 구간 내부의 반복적인 오르막·내리막을 정확하게 재현할 수 없다.

### 현재 적용한 방법

각 휴게소와 출발·도착 지점의 고도를 조회한 뒤 아래 식으로 구간 평균경사를 계산했다.

```text
구간 평균경사(%) = (구간 도착 고도 - 구간 출발 고도) / 구간 거리 × 100
```

계산 결과는 `datas/busan_port_hjit_route_grade.csv`에 저장했다. 서비스 모델은 17개 구간의 거리와 평균경사를 각각 입력해 구간별 kWh/100km와 소비에너지를 예측한다. 노선 평균경사는 화면 요약용으로만 사용하며 에너지 계산을 한 번에 평균값으로 처리하지 않는다.

### 데이터 사용 시 주의사항

- 현재 값은 실제 도로의 순간 최대경사가 아니라 구간 시작·끝 고도 차이를 이용한 평균경사다.
- 구간 내부의 오르막과 내리막이 서로 상쇄될 수 있다.
- Copernicus DEM은 지표면 고도이므로 교량·터널의 실제 도로 높이와 차이가 날 수 있다.
- 상용 운행 정확도를 높이려면 실제 주행 GPS·고도 로그 또는 도로 중심선 종단 프로파일로 교체해야 한다.
- Open-Meteo와 OpenStreetMap 데이터를 상업 환경에서 계속 사용할 경우 각 서비스의 최신 라이선스·이용정책을 별도로 확인해야 한다.
